    部署入門

    部署是什麼：把只在你電腦上跑的程式，變成人人點開就能用的網站

    ⏱ 約 12 分鐘閱讀🎬 影片 20:13入門Claude Code · Vercel · MCP
    Gary Chen · YouTube · 20:13給非技術人員的部署教學，Vibe Coding 上線前必看點擊到 YouTube 觀看影片 ↗
    本節目標：搞懂「部署」到底在做什麼，並學會用三個判斷挑出適合自己專案的平台。學完你能：說出為什麼 localhost 網址傳給別人打不開；判斷自己的專案該放在哪一類平台；知道部署後要檢查後台哪四個區塊。

    這些情況你遇過嗎？

    影片中的例子：Gary 的記帳軟體

    Gary 用 Claude Code 做了一個記帳工具：能登入、能記帳，還能按一下讓 AI 分析這個月的開銷。每次寫完，瀏覽器都會開出一個 localhost:3000 的分頁。他把這串網址傳給朋友，朋友用手機一點——無法連線。

    換成你的工作（示意情境）

    你用 Claude 做了一個機電調試（T&C）檢查表小工具，想讓工地同事用手機打勾回報。你把網址傳到群組，結果大家都打不開；想把整個資料夾寄過去，同事又不會安裝任何開發環境。

    關鍵洞察：localhost 意思是「本機」。它不是你 App 的公開地址，而是叫「正在點連結的那台裝置」去問自己。朋友的手機裡沒有你的程式，所以當然打不開。想讓別人點開就能用，就需要部署。

    部署 = 開一家正式餐廳

    在自己電腦寫程式，就像在家裡廚房試做了一道菜：你自己吃得到，別人吃不到。部署，就是走出家門開一家店。影片把它拆成三件事：

    開餐廳在軟體世界裡為什麼需要
    租店面（24 小時營業）一台永遠開機的雲端伺服器你的筆電會闔上、會帶走，但使用者可能半夜或從地球另一端連進來
    搬廚房（廚具、醬料、食材）程式碼、執行環境、API 金鑰要在遠端也能跑出和本機一樣的結果
    掛招牌固定的公開網址（例如 gary.com）讓全世界的瀏覽器都找得到你的程式

    取得雲端電腦的三條路

    路線做法問題適合誰
    ① 家裡自己養機器筆電不關機，或買迷你主機 24 小時開著停電斷網就掛；把家用網路暴露在公開網路上，有資安風險不建議新手
    ② 租雲端虛擬主機（VPS）DigitalOcean、Linode、AWS Lightsail 等一台「毛胚屋」，作業系統、防火牆、環境都要自己用指令組裝和維護後端／維運工程師
    ③ 託管部署平台Vercel、Netlify、Railway、Cloudflare 等複雜設定都藏在背後；授權 GitHub 後，每次推上新版就自動上線用 AI 做產品的人——影片推薦

    選平台前，先做三層判斷

    別一開始就比較各家平台規格——平台只是工具。先搞清楚你的專案需要什麼，再挑平台。

    判斷 1：需要後端運算嗎？
    需要登入、存資料、呼叫 AI → 動態網站（有後端）
    只是展示內容（作品集、活動頁、純前端小遊戲）→ 靜態網站
    ↓
    判斷 2：全端框架，還是前後端分離？
    開一個終端機視窗、一行指令就能跑 → 全端（例如 Next.js）
    要開兩個視窗分別跑前端和後端 → 前後端分離（例如 React + Python）
    ↓
    判斷 3：雲端電腦要 24 小時開著嗎？
    按一下、幾秒就算完的短動作 → Serverless（按次計費，沒人用就零成本）
    長時間持續跑（影片轉檔、爬蟲、即時聊天室）→ 常駐伺服器（固定月租）

    用餐廳比喻前端與後端

    角色比喻負責什麼
    前端外場按鈕、輸入框、排版、動畫——訪客看得到、摸得到的一切
    後端內場（廚房）算帳、保護密碼、拿 API 金鑰呼叫 AI——不能讓外人看到的敏感運算
    CDN全球連鎖分店把靜態網頁複製到世界各地機房，就近送出，幾乎秒開

    Gary 的判斷結果

    判斷Gary 的記帳軟體結論
    需要後端嗎？要登入、要呼叫 AI 分析動態網站
    架構？只開一個終端機視窗，用 Next.js全端框架
    要一直開著嗎？記帳、AI 分析都是三五秒的短動作Serverless 最省錢

    託管平台地圖

    類別代表平台適合影片的推薦
    靜態網站託管Cloudflare Pages、Vercel、Netlify、GitHub Pages作品集、活動頁、純前端工具Cloudflare Pages（全球節點多、速度快）；要收表單報名就用 Netlify（內建表單收集）
    Serverless 全端託管Vercel（Netlify 也支援）Next.js 等全端框架、短暫運算Vercel——Next.js 是 Vercel 自家開發，整合度最好
    常駐伺服器／容器Railway、Render爬蟲、即時聊天室、獨立後端Railway 或 Render；通常有每月約 5–7 美元的最低費用
    雲端巨頭AWS、Google Cloud、Azure大型企業系統新手不建議——「牛刀殺雞」。上面幾家平台底層多半就是租用這些機房
    Note：各平台的免費額度和價格常會調整，請以官網為準。另外，Vercel 的免費 Hobby 方案限個人、非商業用途；如果是公司內部使用的工具，應考慮付費方案或先和公司 IT 確認。

    動手做：用 AI 部署，再看懂後台

    1. 先讓 AI 幫你做三層判斷

      不確定專案屬於哪一種，就直接問你的 AI。

      提示詞
      請檢查我這個專案，然後用白話回答以下三個問題：
1. 這是純靜態網站，還是需要後端運算的動態網站？（有沒有登入、資料儲存、API 金鑰）
2. 它是全端框架（一個指令就能跑），還是前後端分離（要分開啟動）？
3. 它的功能都是幾秒內完成的短動作，還是需要 24 小時持續運作？
最後，根據以上判斷，建議我應該部署到哪一類平台（靜態託管 / Serverless 全端 / 常駐伺服器），並說明理由。
    2. 到選定的平台註冊帳號

      這是整個流程中少數需要你親自動手的步驟（例如用 GitHub 帳號登入 Vercel）。

    3. 替 AI 裝上該平台的 MCP，讓 AI 代你部署

      用 Vercel 就找 Vercel 的 MCP，用 Netlify 就找 Netlify 的 MCP。MCP 讓 AI Agent 能直接操作平台，幫你上傳與部署。

      提示詞
      我已經在 Vercel 註冊好帳號，並連接了 Vercel MCP。
請幫我把這個專案部署上線：
1. 部署前先確認 .env 檔案沒有被推上 GitHub（有在 .gitignore 裡）。
2. 列出這個專案需要在 Vercel 設定的環境變數「名稱」（不要顯示金鑰內容），我會自己到後台填入。
3. 部署完成後，告訴我部署狀態和公開網址。
每一步執行前先告訴我你要做什麼。
    4. 進後台，看懂四個關鍵區塊
      後台區塊它是什麼你要做什麼
      Deployments
      部署狀態      		每次發布的即時看板看到綠燈 = 程式碼已被雲端接收並打包完成；紅字 = 有錯誤
      Environment Variables
      環境變數      		放 API Key、資料庫密碼的地方把本機 .env 裡的金鑰名稱與內容貼進來，否則功能會壞掉
      Domains
      網域      		網址門牌預設網址帶一串亂碼；想用自己的網域，在這裡綁定
      Logs
      日誌      		網站的即時活動紀錄簿出錯時會跳紅字，複製給 AI，或讓 AI 透過 MCP 直接讀取並修復
    5. 出錯時，把日誌交給 AI
      提示詞
      我的網站部署成功（綠燈），但使用時出錯。以下是 Vercel Runtime Logs 的錯誤訊息：

[貼上紅色錯誤訊息]

請根據這段日誌：
1. 用白話說明問題出在哪裡（例如是不是缺少環境變數）。
2. 告訴我要在程式或後台改什麼。
3. 修好後，教我怎麼確認問題已解決。
    ✅ 成功檢查點：Deployments 亮綠燈、環境變數已填好、（選擇性）綁定了自己的網域、Logs 裡的活動紀錄正常跳動——這時才把連結傳給朋友或同事。

    常見誤解澄清

    誤解 1：本機網址可以直接分享

    ❌ 錯誤認知：瀏覽器能打開 localhost:3000，傳給別人應該也能打開。
    ✅ 正確理解：localhost 指向「點連結的那台裝置」自己，別人的裝置上沒有你的程式。

    誤解 2：部署成功，網站就一定能用

    ❌ 錯誤認知：後台亮綠燈，按鈕就一定有反應。
    ✅ 正確理解：綠燈只代表打包完成。最常見的坑是沒填環境變數，程式找不到金鑰就會壞掉。

    誤解 3：把 .env 推上 GitHub，雲端就拿得到金鑰

    ❌ 錯誤認知：把 .env 一起推上去最方便。
    ✅ 正確理解：.env 絕對不能推上 GitHub，否則全世界都看得到你的密碼。金鑰要填在平台的 Environment Variables。

    誤解 4：要部署就得開 AWS 帳號

    ❌ 錯誤認知：正式上線一定要用 AWS、Google Cloud。
    ✅ 正確理解：對只想快速做出產品的人來說，託管平台就夠了；多付一點錢，換來不用自己維護機房。

    誤解 5：上線了就代表安全

    ❌ 錯誤認知：能部署，就等於產品可以正式使用了。
    ✅ 正確理解：網站一公開，資安風險才開始。小工具分享給朋友沒問題，但正式的 production 軟體需要認真處理資安。
